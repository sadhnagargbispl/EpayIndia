ePay App API

Webapp ke har page (AppLogin se Account Delete tak) ka ek API. Ek hi URL hai, reqtype se kaam badalta hai. Har response valid JSON hai, aur har call server par log hoti hai.

POSThttps://epayindia.in/AppApi.aspx

Request & response

Body raw JSON mein bhejo (Content-Type: application/json). Keys case-insensitive hain. Purani apps jaisa form field MyJson bhi chalega.

Header / fieldKabDetail
reqtypehameshaKaunsi API — neeche har screen par likha hai.
isloginhamesha"N" = login, couponlist, monthlypackages (header mein apikey nahi). "Y" = baaki sab APIs (header mein apikey). Galat value par code: 400.
apikey (header)islogin = "Y"login response ki data.apikey. HTTP header mein bhejo, body mein nahi.
useridhar API mein (common list chhod ke)Member ID, jaise web login mein.
passwdhar API mein (common list chhod ke)Member ka password. Server log mein **** ho jata hai.
deviceidoptionalDevice ki unique id. Log mein jati hai, support ke liye kaam aati hai.
appversionoptionalLog mein jata hai, support ke liye kaam aata hai.
Success
{"response":"OK","code":200,"msg":"","reqtype":"walletbalance","reqid":"20260924153012345482","data":{"walletbalance":1250.00}}
Failure
{"response":"FAILED","code":400,"msg":"Insufficient Balance!!","reqtype":"couponpurchase","reqid":"20260924153101874021","data":null}

HTTP status hamesha 200 aata hai. Result response aur code se check karo, aur user ko msg dikhao. data failure par null hota hai. Amount JSON number hain (string nahi).

Codes & errors

codeMatlabApp kya kare
200Success—
400Galat input ya business rule (balance kam, package allowed nahi…)msg dikhao
401userid / passwd galat (password badal gaya ho), ya apikey nahi / purani hai (dusre device par login ya logout)Saved ID-password delete karo, Login screen par bhejo
403ID block haimsg dikhao, logout karo
404Package / order / member nahi milamsg dikhao
405POST ke alawa methodPOST use karo
409Same request 20 second ke andar dobara aayi (pichhli chal rahi hai ya ho chuki hai)msg dikhao, thodi der baad try karo
500Server errorRetry option; support ko reqid do

userid, passwd & apikey

  • Har API mein userid aur passwd bhejna zaroori hai. Server har call par web login jaisa hi check karta hai (sp_Login1).
  • Sirf common lists mein nahi chahiye, jo sabke liye same hoti hain: couponlist, monthlypackages.
  • Har API mein islogin bhejo: login, couponlist, monthlypackages mein "N", baaki sab mein "Y".
  • islogin: "Y" wali API mein HTTP header apikey bhejo (login response ki data.apikey). Apikey isi member ki honi chahiye.
  • Har login par nayi apikey milti hai aur purani band ho jati hai. logout par bhi band ho jati hai.
  • login successful ho jaye to app ID-password aur apikey secure storage mein rakhe (Android Keystore / iOS Keychain), plain SharedPreferences mein nahi.
  • code: 401 aaye (jaise password badal gaya) to saved details hata ke Login screen par bhejo.
  • Missing userid ya passwd par code: 400 aata hai.

Double tap se bachao

App ko transid nahi bhejna hai. Paisa ya request wali APIs (couponpurchase, subscriptionpay, monthlyactivate, deleteaccount) mein server transaction number khud banata hai.

  • Same user ki same API pichhli request ke 20 second ke andar dobara aaye to code: 409 milta hai. Yeh tab hota hai jab pichhli request abhi chal rahi ho ya successful ho chuki ho. Isse double tap ya network retry par do baar paisa nahi katega.
  • Phir bhi button dabate hi use disable kar do, aur response aane tak "Please wait" dikhao.
  • 409 aaye to user ko msg dikhao. Pichhla result dekhna ho to wallet balance ya order ki screen refresh karo.

Payment flow (Subscription & Activation Points)

subscriptionpay / monthlyactivate→data.paymenturl WebView mein kholo→UPI payment→gateway webhook activation karta hai→paymentstatus
  • paymenturl ko WebView (ya Custom Tab) mein kholo.
  • WebView ka URL Appsubscription-now.aspx, Appmonthly-activation-points.aspx ya AppLogin.aspx par pahunche to WebView band kar do. Activation server par ho chuka hota hai.
  • Phir paymentstatus ko orderid ke saath call karo. Status PENDING ho to 5–10 second ke gap par 3–4 baar dobara check karo.

WebView bridge

Home ke kuch links site ke web pages hain (jaise Store). Unke liye home response mein har item ke saath do fields aati hain:

  • screen — agar app ki apni screen hai (couponlist, subscription, monthly, deleteaccount, home) to wahi kholo.
  • openurl — screen khali ho to yeh URL WebView mein kholo. Site ke pages ke liye yeh AppWebBridge.aspx?page=…&token=… hota hai, jo user ko web par bhi login kar deta hai. Yeh link 1 din chalta hai, aur home dobara call karne par naya link milta hai (purana band ho jata hai). Isliye link save mat karo, har baar home ke latest response se lo. target _blank ho to external browser bhi use kar sakte ho.

Logs (support)

Har call ka ek row Tbl_AppApiLog mein banta hai. Isme request (password/token masked), response, status, time aur member hota hai. Gateway ya wallet ki bahar wali calls Tbl_AppApiExtCallLog mein jati hain. Agar DB log fail ho jaye to Logs/AppApi_yyyyMMdd.txt mein likha jata hai.

User problem bataye to app se reqid lo aur yeh query chalao:

SQL
SELECT * FROM Tbl_AppApiLog WHERE ReqID = '20260924101507009012';
SELECT * FROM Tbl_AppApiExtCallLog WHERE ReqID = '20260924101507009012';

-- Ek din ke saare errors
EXEC Sp_AppApiLog_Search '2026-09-24', '2026-09-24', @Status = 'ERROR';

Status = ERROR aur ErrorMsg mein "MASTER WALLET DEBITED BUT VOUCHER NOT CREATED" dikhe to us case ko reconcile karna hai. Debit ka ref no RefNo column mein milega.
